# 組織ツリー設計書 (Materialized Path 方式)

## 1. 階層ツリー構造の管理方式
組織構造（本社 -> 開発統括部 -> 第1開発部 -> フロントエンドチームなど）は任意階層のツリー構造です。
高速な配下部署探索およびIDOR認可判定を実現するため、**Materialized Path（実体化パス方式）** を採用します。

### 1.1 カラム構成
- `id`: UUID (例: `d1000000-0000-0000-0000-000000000001`)
- `parentId`: 親部署ID (NULL許容)
- `path`: `/root-id/parent-id/self-id` 形式の階層パス文字列
- `level`: 階層の深さ (1, 2, 3...)

### 1.2 配下部署の高速クエリ
部署長（DEPARTMENT_MANAGER）が `dept-123` に所属している場合、自身および全配下部署のID一覧は以下のSQLでインデックス検索されます：

```sql
SELECT id FROM departments WHERE path LIKE '/.../dept-123%'
```

### 1.3 部署移動・階層再編時の整合性
親部署が変更された場合、その部署およびすべての配下部署の `path` と `level` を単一のトランザクション内で再帰的に一括更新します。
これにより、常にデータ整合性が保たれます。
