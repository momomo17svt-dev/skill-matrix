# セキュリティ設計書

## 1. 認証とセッション保護
1. **パスワード保護**:
   - `bcrypt` ハッシュアルゴリズム（ストレッチング10ラウンド以上）を採用。平文パスワードは即座にメモリから解放。
2. **ブルートフォース攻撃防御 (アカウントロック)**:
   - 連続5回の認証失敗でアカウントを15分間ロック (`lockedUntil` カラム)。
   - ロック期間中の認証試行は即座に拒絶。
3. **セッション固定化 (Session Fixation) 攻撃防御**:
   - ログイン成功時、古いセッションを破棄し、新しい暗号論的トークン（32バイト乱数）を発行。
4. **Cookie セキュリティ**:
   - `HttpOnly`: JavaScriptからの不正読み取り（XSSによるセッション盗用）を防止。
   - `SameSite=Lax`: CSRF攻撃を防止。
   - `Secure`: HTTPS接続時に強制（開発環境設定で柔軟に切替可能）。

## 2. 認可 (RBAC) & IDOR 防御アーキテクチャ
- バックエンドの各ルートハンドラは、中間層 `requireRole` および `requireDepartmentScope` ガードを通過します。
- `DEPARTMENT_MANAGER` は、自身の `department.path` を前方一致検索し、管理下にある部署IDセットを動的解決して認可判定を行います。
- `GENERAL` は、更新系エンドポイントにおいて対象の `employeeId === currentSession.employeeId` であること、かつ許可された変更項目（自己評価・自身の資格・実務経歴など）のみであることを厳格に検証します。

## 3. 入力値検証 & 出力エスケープ
- すべてのリクエストペイロードは、`packages/shared` の Zod スキーマにより型および制約（文字数、文字種、MIMEタイプ、日付フォーマット）を厳格にバリデーション。
- ReactによるHTML自動エスケープに加え、APIエラーメッセージにもサニタイズを適用。

## 4. ログマスキング & エラー隠蔽
- ロガー（`logger.ts`）は、リクエストボディやログパラメータから `password`, `token`, `cookie`, `secret` 等の機密キーを検知し、`***MASKED***` へ置換。
- 未処理の内部例外（PrismaのSQLエラーやシステム例外）が発生した場合、クライアントには汎用エラー `{ success: false, error: { code: "INTERNAL_SERVER_ERROR", message: "内部エラーが発生しました。" } }` のみを返し、詳細なスタックトレースはRequest IDとともにサーバー側ログにのみ記録。
