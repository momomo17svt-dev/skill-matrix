# ファイルストレージ及び安全な削除設計書

## 1. ファイル保存方針
- 資格証明書・賞状等の添付ファイル本体は SQL Server に直接格納せず、ローカルファイルストレージ（設定された `UPLOAD_DIR`）に安全に保存します。
- DBの `certification_attachments` テーブルには、ファイルメタデータ（元ファイル名、UUID保存ファイル名、相対パス、MIMEタイプ、ファイルサイズ、SHA-256ハッシュ値）のみを格納します。

## 2. セキュリティ検証フロー
1. **ファイルサイズ検証**: 10MB (10,485,760 bytes) 超過は即座に拒絶。
2. **拡張子検証**: `.pdf`, `.png`, `.jpg`, `.jpeg` のホワイトリストチェック。
3. **MIME / マジックナンバー検証**: ファイル先頭バイト列（マジックナンバー）をチェックし、Content-Typeの偽装を防止。
4. **ファイル名安全性**: 保存時は `uuidv4() + '.' + safeExt` の形式で生成し、元ファイル名はDBメタデータにのみ退避（Path Traversalの完全遮断）。
5. **VirusScanner インターフェース**:
   ```typescript
   export interface VirusScanner {
     scanFile(filePath: string): Promise<{ isClean: boolean; virusName?: string }>;
   }
   // デフォルトは NoOpVirusScanner、将来 ClamAV 等のアダプタを接続可能
   ```

## 3. トランザクション補償付き削除フロー (DB & ファイル整合性)
1. 社員削除または資格削除時、削除対象となる添付ファイルの物理パス一覧を事前にメモリ上に取得。
2. DBトランザクションを実行し、関連レコード（資格メタデータ、経歴、評価等）を物理削除。
3. DBトランザクションが **正常にコミット完了** した後、メモリ上の物理ファイルを非同期/順次安全に削除。
4. DBトランザクションがロールバックされた場合は、物理ファイルの削除を行わない。
5. 物理ファイル削除時に万一OSエラーが発生した場合は、エラーログを記録し、定期クリーンアップタスクで孤立ファイルを安全に検知・削除。
